# Информационная безопасность и защита данных

Задания 1, 3 и 4 на Python 3.12 или новее. Дополнительные библиотеки не нужны.

## Что где лежит

| Папка | Содержимое |
|---|---|
| `task_01_disk_auditor` | Ревизор и два примера: `examples/known.bin`, `examples/nested/note.txt` |
| `task_03_vigenere` | Виженер: текст и ключ вводятся в консоли, примеры-файлы не нужны |
| `task_04_gamma` | Гаммирование и один исходник `examples/message_utf8.txt` |
| `tools` | Общий ввод, обработка ошибок и сохранение файлов |
| `materials` | Только оригиналы из архива: условия и `secret.txt` в CP1251 с текстом `я A` |
| `output` | Шифротексты и восстановленные файлы; создаётся при сохранении, не попадает в Git |

У ревизора алгоритм находится в `auditor.py`, запуск — в `__main__.py`. В заданиях 3 и 4 `cipher.py` содержит алгоритм, `encrypt.py` и `decrypt.py` — отдельные программы. `__init__.py` обозначают пакеты Python.

В `examples` лежат только исходные данные. Результаты создаются запуском программ. `output` можно удалить, когда результаты больше не нужны: при следующем сохранении папка появится снова.

## Перед запуском

Откройте терминал в корне репозитория — рядом с этим README. Проверьте версию:

```powershell
python --version
```

Пути ниже отсчитываются от корня репозитория; вводите их в диалоге без кавычек. **Enter** означает нажать клавишу, ничего не вводя. Если выходной файл уже существует, дополнительно подтвердите перезапись ответом `да`.

## Задание 1: ревизор диска

```powershell
python -m task_01_disk_auditor
```

На вопрос «Каталог для проверки» введите `task_01_disk_auditor/examples`.

Первый запуск проверит два файла и создаст в этой папке `.integrity.json`. Повторный запуск должен вывести `Изменений не обнаружено.`. Эталон не проверяет сам себя и не попадает в Git.

**Что показать преподавателю:**

1. Выполнить первый и повторный запуск: создание эталона и отсутствие изменений.
2. Дописать `!` в `task_01_disk_auditor/examples/nested/note.txt`, удалить `task_01_disk_auditor/examples/known.bin` и создать `task_01_disk_auditor/examples/new.txt` с любым текстом.
3. Повторить проверку: показать изменённый, удалённый и добавленный файлы.
4. Ответить `нет` на обновление эталона. При следующем запуске отличия останутся видны.
5. Ответить `да`. Следующая проверка покажет отсутствие изменений.

Чтобы повторить демонстрацию с исходными данными, восстановите два примера командой ниже, затем удалите созданные при демонстрации `new.txt` и `.integrity.json` из папки `examples`:

```powershell
git restore -- task_01_disk_auditor/examples
```

**Как объяснить алгоритм:** `os.walk()` обходит каталог и подпапки. Каждый файл читается порциями по `64 * 1024` байтов. Пары байтов образуют 16-битные числа: `(первый << 8) | второй`. Числа последовательно объединяются через XOR; непарный последний байт дополняется нулём только в памяти. Для каждого относительного пути сохраняется сумма. Затем сравниваются пути и суммы: новый путь — добавление, исчезнувший — удаление, другая сумма — изменение.

Пример `known.bin` содержит `01 02 03`: `0102 XOR 0300 = 0202`. XOR-16 допускает совпадение сумм разных файлов, поэтому обнаруживает не все изменения содержимого. Ссылки пропускаются, ошибка чтения останавливает проверку.

## Задание 3: Виженер

Запустите шифратор:

```powershell
python -m task_03_vigenere.encrypt
```

| Вопрос программы | Что ввести |
|---|---|
| Текст для шифрования | `ЕёЯ, 123!` |
| Ключ | `б` |
| Файл для шифротекста | Enter → `output/vigenere.txt` |

Ожидаемый шифротекст: `ЁжА, 123!`. Шифратор завершит работу. Теперь отдельно запустите дешифратор:

```powershell
python -m task_03_vigenere.decrypt
```

| Вопрос программы | Что ввести |
|---|---|
| Файл с шифротекстом | Enter → `output/vigenere.txt` |
| Ключ | `б` |
| Сохранить текст в файл? | `да` |
| Файл для текста | Enter → `output/vigenere_restored.txt` |

**Что показать преподавателю:** исходный текст, созданный шифротекст и восстановление `ЕёЯ, 123!` отдельным запуском. Можно повторить с ключом `ключ`, чтобы показать повторение многобуквенного ключа.

**Как объяснить алгоритм:** у 33 русских букв, включая `ё`, есть индексы от 0 до 32. Ключ повторяется по русским буквам текста. При шифровании индексы буквы текста и буквы ключа складываются по модулю 33; при расшифровании индекс ключа вычитается. Регистр сохраняется. Пробелы, цифры, пунктуация и нерусские символы не меняются и не продвигают ключ. Файлы записываются в UTF-8.

## Задание 4: гаммирование

Запустите шифратор:

```powershell
python -m task_04_gamma.encrypt
```

| Вопрос программы | Что ввести |
|---|---|
| Исходный текстовый файл | `task_04_gamma/examples/message_utf8.txt` |
| Соль | `пример` |
| Кодировка | Enter → `utf-8` |
| Файл для шифротекста | Enter → `output/gamma.bin` |

После завершения шифратора отдельно запустите дешифратор:

```powershell
python -m task_04_gamma.decrypt
```

| Вопрос программы | Что ввести |
|---|---|
| Файл с шифротекстом | Enter → `output/gamma.bin` |
| Сохранить текст в файл? | `да` |
| Файл для текста | Enter → `output/gamma_restored.txt` |

Программа сама прочитает соль из файла, выведет `пример` и исходный текст. Восстановленный файл должен побайтово совпасть с исходником. Проверить в PowerShell:

```powershell
(Get-FileHash task_04_gamma/examples/message_utf8.txt).Hash -eq (Get-FileHash output/gamma_restored.txt).Hash
```

Ожидается `True`. Дополнительный короткий пример из архива: при шифровании укажите `materials/secret.txt`, соль `пример` и кодировку `cp1251`. После расшифрования получится `я A`.

**Что показать преподавателю:** исходный файл, создание отдельного шифротекста, завершение шифратора, отдельный запуск дешифратора, вывод соли и восстановленного текста.

**Как объяснить алгоритм:** файл читается как байты. Соль задаёт начальное состояние `random.Random(salt)`. Для каждого байта файла `getrandbits(8)` выдаёт один байт гаммы, и выполняется XOR. В выходном файле первая строка — JSON с солью и кодировкой, после перевода строки идут зашифрованные байты. Дешифратор создаёт генератор с той же солью и повторяет XOR: `(A XOR G) XOR G = A`.

Кодировка нужна для чтения байтов как текста, сам XOR от неё не зависит. UTF-8 используется по умолчанию; CP1251 нужна для исходного `secret.txt`. Шифрование и расшифрование выполняйте одной версией Python. Это учебная схема: соль хранится открыто, секретного ключа нет, `random` не является криптографическим генератором.
